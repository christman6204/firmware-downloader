## 1. 项目概述

### 一句话描述

**固件下载器**：从 SD 卡或 MCU 内部 Flash 读取固件文件，通过 USART1 按自定义协议分段发送至目标设备，完成固件下载与更新触发。

### 硬件平台

- MCU: STM32F103VET6 (Cortex-M3, 72MHz, 512KB Flash, 64KB SRAM)
- 存储: SPI 模式 SD 卡 (SPI2, PB13/14/15, CS=PD8)
- 人机接口: 2 个按键 (PB11, PE14) + 4 个 LED (PB12, PA5, PA12, PC10) + 1 个蜂鸣器 (PA3)
- 通信: USART1 (PA9/PA10, 38400-8N1, 连接目标设备) + USART2 (PD5/PD6, 115200-8N1, 调试输出)
- 看门狗: IWDG (4s 超时)

### 软件架构总览

```
+------------------------------------------------------------------+
|                        UCOS-III RTOS                              |
|  Tick(10)  Tmr(22)  Stat(23)  Idle(31)                           |
+------------------------------------------------------------------+
|  AppTaskStart(26) | AppTaskKey(25)                               |
|  (启动+监控)      | (按键扫描)                                   |
+------------------------------------------------------------------+
|  AppTaskLED_WDG(28)                    | AppTaskDownload(20)     |
|  (LED+IWDG+蜂鸣器)                     | (下载状态机-核心)       |
+------------------------------------------------------------------+
|                         IPC 层                                    |
|  g_key_event_q(OS_Q,8)  g_usart1_rx_sem(OS_SEM)                  |
|  g_state_mutex(OS_MUTEX)                                         |
|  蜂鸣器: Buzzer_Request() 直接写入 task_led_wdg (无队列)          |
+------------------------------------------------------------------+
|  App 逻辑层: sys_state | crc32 | protocol | sd_card               |
+------------------------------------------------------------------+
|  BSP 层: bsp_gpio | bsp_usart | bsp_spi_sd | bsp_iwdg            |
+------------------------------------------------------------------+

+------------------------------------------------------------------+

+------------------------------------------------------------------+
```

### 3.3 启动流程

`main()` 调用 `OSInit()` 后创建 `AppTaskStart` (Prio 26)，`OSStart()` 启动调度器后执行以下步骤：

1. **BSP / CPU / SysTick / Mem 初始化**
   - `BSP_Init()`: GPIO + IWDG + USART + SPI2 硬件初始化
   - `CPU_Init()`: uC/CPU 层初始化
   - `BSP_CPU_ClkFreq()`: 读取并校验 HCLK = 72MHz (非 72MHz 则软复位)
   - `OS_CPU_SysTickInit(cnts)`: 初始化 SysTick 为 500Hz
   - `Mem_Init()`: uC/LIB 内存管理初始化 (4KB 堆)

2. **统计任务基线校准** (`OSStatTaskCPUUsageInit`)

3. **使能时间片轮转** (`OSSchedRoundRobinCfg(DEF_ENABLED, 0, ...)`)

4. **系统状态初始化** (`SysState_Init()`: 创建 "State Mutex"，默认 SD_CARD / NORMAL / unlocked)

5. **SD 卡初始化** (`SD_Init()`: SPI2 + SD 卡 SPI 模式 + f_mount)
   - 成功：触发 BOOT 蜂鸣 (Buzzer_Request(BUZZER_CMD_BOOT))
   - 失败：触发 ERROR 蜂鸣 (Buzzer_Request(BUZZER_CMD_ERROR))，通过 USART2 打印警告，不阻塞启动

6. **创建 IPC 对象**
   - `g_key_event_q` (OS_Q, "Key Q", 深度 8)
   - `g_usart1_rx_sem` 已由 `BSP_USART_Init` 创建 (初值 0)
   - 蜂鸣器通过 `Buzzer_Request()` 函数直接写入 `task_led_wdg` 的共享变量，无需独立队列

7. **创建 3 个业务任务** (按优先级从高到低)
   - `AppTaskDownload` (Prio 20, 栈 4096B)
   - `AppTaskKey` (Prio 25, 栈 1024B)
   - `AppTaskLED_WDG` (Prio 28, 栈 1024B)

8. **就绪消息** (USART2 打印 "FW Downloader V2.0 Ready.")

9. **1s 监控循环** (不删除 `AppTaskStart`，保留为最低业务优先级监控)

## 4. 模块详细说明

### 4.1 bsp_gpio -- GPIO 驱动

**文件:** `bsp/bsp_gpio.h`, `bsp/bsp_gpio.c`

**职责:** 初始化所有 GPIO (LED/按键/蜂鸣器/SD_CS)，提供 LED 亮灭/翻转、按键读取、蜂鸣器开关、SD 卡片选的原子操作。

**依赖:** `stm32f10x.h` (SPL)

**被依赖:** 所有需要操作硬件的模块 (task_led_wdg, task_key, task_download, bsp_spi_sd)

**关键接口:**

| 函数 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `BSP_GPIO_Init()` | 无 | void | 初始化所有 GPIO 时钟、模式。LED 推挽输出高电平(灭)，按键上拉输入，SD_CS 推挽输出高(取消选中)。蜂鸣器初始化后显式关闭确保上电静音 |
| `BSP_LED_On(port, pin)` | GPIO端口, 引脚 | void | 低电平亮 (GPIO_ResetBits) |
| `BSP_LED_Off(port, pin)` | GPIO端口, 引脚 | void | 高电平灭 (GPIO_SetBits) |
| `BSP_LED_Toggle(port, pin)` | GPIO端口, 引脚 | void | 翻转 ODR 位 (port->ODR ^= pin) |
| `BSP_Key_Read(key_id)` | KEY_ID_1=1 / KEY_ID_2=2 | uint8_t: 0=按下, 1=释放 | 读 GPIO 输入电平 |
| `BSP_Buzzer_On()` | 无 | void | PA3 低电平 (蜂鸣器低电平有效, GPIO_ResetBits 响) |
| `BSP_Buzzer_Off()` | 无 | void | PA3 高电平 (GPIO_SetBits 静音) |
| `BSP_SD_CS_Low()` | 无 | void | PD8 低电平 (选中 SD 卡) |
| `BSP_SD_CS_High()` | 无 | void | PD8 高电平 (取消选中) |

**设计要点:**
- LED 低电平有效 (GPIO_ResetBits 亮 / GPIO_SetBits 灭)，与常规推挽输出 LED 驱动电路一致
- 蜂鸣器 (PA3) 低电平有效，与 LED (低电平有效) 一致。`BSP_GPIO_Init` 末尾显式调用 `BSP_Buzzer_Off()` 避免上电瞬间误响
- LED 输出速度设 2MHz 以降低 EMI (不需要快速切换)
- SD_CS 输出速度设 50MHz 以适配 SPI 高速模式
- 按键使用内部上拉 (GPIO_Mode_IPU)，外部无需上拉电阻

### 4.2 bsp_usart -- USART 驱动

**文件:** `bsp/bsp_usart.h`, `bsp/bsp_usart.c`

**职责:** USART1 (PA9/PA10) 中断接收 + TIM3 超时/字节数帧结束判定，用于与目标设备通信；USART2 (PD5/PD6) 阻塞式调试打印输出。

**依赖:** `stm32f10x.h`, `os.h`, `<stdio.h>`, `<stdarg.h>`

**被依赖:** task_download (USART1 收发), 所有模块的调试打印 (USART2)

**关键接口:**

| 函数 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `BSP_USART_Init()` | 无 | void | 初始化 USART1 (38400-8N1, RXNE 中断 + TIM3 超时/字节数判定, NVIC 抢占优先级 1) + USART2 (115200-8N1, 部分重映射到 PD5/PD6)。PA10 (RX) 配置为内部上拉 (IPU)。创建 `g_usart1_rx_sem` (初值 0)，启动 TIM3 10ms 周期计时 |
| `BSP_USART1_Send(buf, len)` | 数据指针, 长度 | void | 阻塞发送整帧 (等待 TXE, 最后等 TC) |
| `BSP_USART1_RecvStart()` | 无 | void | 复位接收计数器 (g_rx_len=0)，使能 RXNE 中断 |
| `BSP_USART1_GetRecvLen()` | 无 | uint16_t | 返回已接收字节数 |
| `BSP_USART1_GetRecvBuf()` | 无 | const uint8_t* | 返回接收缓冲指针 (g_rx_buf) |
| `BSP_USART2_Printf(fmt, ...)` | 格式化字符串+变参 | void | 阻塞发送格式化的调试文本 (内部缓冲 256B, 逐字节 USART_SendData) |
| `BSP_USART1_IRQHandler()` | 无 | void | RXNE 中断存字节到 g_rx_buf；重置 TIM3 超时计数；累积 >128 字节立即关 RXNE 中断并 Post 信号量 |
| `BSP_USART1_TIMEOUT_Handler()` | 无 | void | TIM3 超时中断处理 (10ms 周期)：递减超时计数；归零且已收到数据则关 RXNE 中断并 Post 信号量 |
| `BSP_USART1_GetRxFlags()` | 无 | uint8_t | 返回帧结束时 SR 的错误标志 (ORE/NE/FE) |
| `BSP_USART1_GetRxMaxGapMs()` | 无 | uint32_t | 返回本次接收中相邻字节最大间隔 (ms) |

**设计要点:**
- 接收缓冲 `g_rx_buf` 为 512 字节，`g_rx_len` 为 volatile 防止编译器优化掉写入
- 帧结束判定改用 TIM3 超时 + 字节数阈值（去掉 IDLE 中断，避免线路空闲时 IDLE 标志常置位导致 ISR 死循环）：
  - 字节间间隔超过 `RX_TIMEOUT_MS` (80ms) 无新数据，即认为一帧接收完成
  - 累积字节数 > `RX_FRAME_READY_LEN` (128) 立即上报应用层
  - 任一条件满足即关闭 RXNE 中断并 Post `g_usart1_rx_sem`；设备回复可能不连续，须等待完整应答帧再解析
- PA10 (RX) 配置为内部上拉 (`GPIO_Mode_IPU`)，抑制空闲噪声
- USART1 上电自测（回环）已移除：上电不再执行串口自检，仅完成初始化
- `BSP_USART2_Printf` 使用 `vsnprintf` 格式化后逐字节阻塞发送；对 `vsnprintf` 截断返回值做了钳位保护 (防越界)
- USART2 使用部分重映射 (GPIO_Remap_USART2) 将引脚从 PA2/PA3 移到 PD5/PD6，避免与蜂鸣器 (PA3) 冲突
- 信号量超时由 `app_cfg.h` 配置：Start/Data/Update/Terminate 命令用 `APP_CMD_TIMEOUT_TICKS` (500 ticks = 1s @500Hz)；Complete 命令用 `APP_CMD_COMPLETE_TIMEOUT_TICKS` (4000 ticks = 8s @500Hz)

### 4.3 bsp_spi_sd -- SPI2 + SD 卡驱动

**文件:** `bsp/bsp_spi_sd.h`, `bsp/bsp_spi_sd.c`

**职责:** SPI2 初始化和 SD 卡 SPI 模式底层驱动 (CMD0 -> CMD8 -> ACMD41 初始化序列 + CMD17 单块读)。

**依赖:** `stm32f10x.h`, `bsp_gpio.h`

**被依赖:** diskio.c (FatFs 适配层), sd_card.c (应用层 SD 封装)

**关键接口:**

| 函数 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `BSP_SPI2_Init()` | 无 | void | SPI2 初始化: PB13=SCK / PB14=MISO / PB15=MOSI, Mode3 (CPOL=1,CPHA=1), 256 分频 (~140kHz), 8-bit MSB, 软件 NSS |
| `SD_SPI_SetHighSpeed()` | 无 | void | SPI2 提速至 2 分频 (18MHz)，用于初始化完成后的正常读写 |
| `SD_SPI_Init()` | 无 | uint8_t: 0=成功, 1=失败 | SD 卡 SPI 模式初始化: 74+ 时钟 -> CMD0 (重试100次) -> CMD8 (电压检测+SD v2.0识别) -> CMD55+ACMD41 (HCS=1支持SDHC, 重试1000次) -> 提速至18MHz |
| `SD_SPI_ReadBlock(addr, buf)` | 扇区地址, 512B缓冲 | uint8_t: 0=成功, 1=R1错误, 2=Token超时 | CMD17 单块读: CS低 -> 发CMD17 -> 等待R1=0x00 -> 等待0xFE Token -> 读512B -> 读2B CRC16(忽略) -> CS高 |

**设计要点:**
- 初始化阶段 SPI 速度 ~140kHz (PCLK2/2/256 = 36MHz/256)，满足 SD 规范 <400kHz 要求；就绪后提速至 18MHz
- 使用 SPI Mode 3 (CPOL=1, CPHA=1)，空闲时钟为高、第二沿采样，适配 SD 卡 SPI 模式
- ACMD41 参数携带 HCS=1 (bit30)，支持 SDHC 卡 (>=2GB) 按扇区寻址；对于 SD v1.x 卡 (CMD8 返回 0x05)，HCS 位被忽略，兼容标准容量卡
- `SD_SPI_ReadBlock` 地址参数直接作为 CMD17 的参数 (扇区号)，适用于 SDHC 模式
- CRC16 在 SPI 模式下可忽略，但必须读走 2 字节以推进总线状态机

### 4.5 sys_state -- 系统全局状态

**文件:** `app/sys_state.h`, `app/sys_state.c`

**职责:** UCOS-III 互斥量保护的系统全局状态管理。三类状态：数据源(DataSource)、固件类型(FwType)、传输锁(TransferLock)。

**依赖:** `os.h`, `app_cfg.h`

**被依赖:** task_key, task_download, task_led_wdg

**关键接口:**

| 函数 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `SysState_Init()` | 无 | void | 创建互斥量 "State Mutex"，置默认状态 (SD_CARD, NORMAL, unlocked=0) |
| `SysState_GetDataSource()` | 无 | `DataSource_t` | Pend 互斥量 -> 读 g_data_source -> Post 互斥量 -> 返回 |
| `SysState_SetDataSource(src)` | SD_CARD / MCU_FLASH | void | Pend -> 写 -> Post |
| `SysState_GetFwType()` | 无 | `FwType_t` | Pend -> 读 g_fw_type -> Post -> 返回 |
| `SysState_SetFwType(type)` | NORMAL / FACTORY | void | Pend -> 写 -> Post |
| `SysState_IsTransferLocked()` | 无 | uint8_t: 0=未锁, 非0=已锁 | Pend -> 读 g_transfer_locked -> Post -> 返回 |
| `SysState_SetTransferLock(locked)` | 0/非0 | void | Pend -> 写 -> Post |

**设计要点:**
- 单一互斥量 `g_state_mutex` 保护所有三类状态：字段间无因果依赖，多锁无收益且引入死锁风险；临界区极短(读/写一个字)，锁竞争概率低
- Get 模式: Pend(阻塞) -> 复制到局部变量 -> Post -> return 局部变量，最小化临界区
- `SysState_GetLEDBlinkPeriod` 不在临界区内计算周期值，只在临界区内读取 `g_data_source`
- Pend 超时参数为 0 (OS_OPT_PEND_BLOCKING 无限等待)，不会失败返回

### 4.6 crc32 -- CRC32 查表计算

**文件:** `app/crc32.h`, `app/crc32.c`

**职责:** 标准 CRC32 (Ethernet/zlib/MPEG-2) 纯逻辑模块，查表实现，无硬件依赖。

**依赖:** `<stdint.h>` (仅此一个)

**被依赖:** task_download (整包 CRC32 + 段 CRC32)

**关键接口:**

| 函数 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `CRC32_Reset()` | 无 | void | g_crc_state = 0xFFFFFFFF |
| `CRC32_Update(data, length)` | 数据指针, uint16_t 长度 | void | 逐字节查表更新 g_crc_state。单次最多 65535 字节 |
| `CRC32_GetResult()` | 无 | uint32_t | g_crc_state ^ 0xFFFFFFFF (最终异或) |
| `CRC32_Calc(buf, len)` | 数据指针, uint32_t 长度 | uint32_t | 一次性计算: Reset -> 按 65535 分块 Update -> GetResult |

**CRC32 参数表:**

| 参数 | 值 | 说明 |
|------|----|------|
| 多项式 (reflected) | 0xEDB88320 | 反射形式, 对应标准多项式 0x04C11DB7 |
| 初始值 | 0xFFFFFFFF | 寄存器初值 (全1) |
| 输入反射 | 是 | 每字节 bit-reverse 后处理 |
| 输出反射 | 是 | 最终 CRC 值 bit-reverse |
| 输出异或 | 0xFFFFFFFF | 最终 XOR |
| 查表项数 | 256 x uint32_t | const 固化在 Flash |

**设计要点:**
- 256 项查表 `crc32_table_flash` 是 `const` 全局数组，编译器将其放入 Flash (.rodata 段)，不占用 RAM
- 表已用标准测试向量验证: CRC32("123456789") = 0xCBF43926, 空串 CRC32 = 0x00000000
- `CRC32_Calc` 对 >65535 字节自动分块 (uint16_t 限制)，用 76800 字节测试向量验证与 zlib 一致
- 模块为纯逻辑，不依赖 SPL/UCOS，可在 PC 端用 Python 独立验证 (Tests/test_crc32.py)

### 4.7 protocol -- 协议帧编解码

**文件:** `app/protocol.h`, `app/protocol.c`

**职责:** 下载器通信协议的帧组装 (Build)、帧解析 (Parse)、校验和计算、5 条命令构造器、应答解析器。纯逻辑模块。

**依赖:** `<stdint.h>`, `app_cfg.h`

**被依赖:** task_download (所有帧收发)

**关键接口:**

| 函数 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `Proto_Checksum(buf, len)` | 数据指针, 长度 | uint8_t | sum buf[0..len-1], 返回 ~sum |
| `Proto_BuildFrame(cmd, cmd_len, out, out_len)` | 命令内容, 内容长度, 输出缓冲, 输出长度指针 | uint16_t: 总帧长, 0=失败 | 组装完整帧 (header+checksum+字段+tail) |
| `Proto_ParseFrame(raw, raw_len, cmd, cmd_len)` | 原始数据, 原始长度, 输出命令缓冲, 输出命令长度 | uint8_t: 0=OK, 非0=错误码 | 解析完整帧 (验证 header/length/tail/checksum, 提取 cmd) |
| `Proto_BuildStartCmd(...)` | fw_type, fw_ver, fw_size, fw_crc + out | uint16_t | 构建 START 命令帧 (14B cmd) |
| `Proto_BuildDataCmd(...)` | fw_type, fw_ver, seg_size, seg_crc, offset, data, data_len + out | uint16_t | 构建 DATA 命令帧 (16B+data cmd) |
| `Proto_BuildCompleteCmd(...)` | fw_type, fw_ver, fw_size, fw_crc + out | uint16_t | 构建 COMPLETE 命令帧 (12B cmd) |
| `Proto_BuildTerminateCmd(...)` | fw_ver, fw_size + out | uint16_t | 构建 TERMINATE 命令帧 (8B cmd) |
| `Proto_BuildUpdateCmd(update_type, out, out_len)` | update_type + out | uint16_t | 构建 UPDATE 命令帧 (2B cmd) |
| `Proto_ParseReply(raw, raw_len, reply_type, status, content, content_len)` | 原始数据, 原始长度 + 输出参数 | uint8_t: 0=OK | 解析应答帧: 提取 cmd[0]=reply_type, cmd[1]=status, cmd[2..]=content |

**常量定义:**

| 常量 | 值 | 说明 |
|------|----|------|
| `FRAME_HEADER{0-3}` | FE EF ED FC | 帧头魔数 |
| `FRAME_TAIL{0-3}` | FD EC F8 F1 | 帧尾魔数 |
| `FRAME_FIXED_LEN` | 16 | Header..MsgType 固定字段长度 |
| `FRAME_TAIL_LEN` | 4 | 帧尾长度 |
| `FRAME_MAX_CMD_LEN` | 300 | CmdContent 最大长度 |
| `FRAME_MAX_TOTAL` | 320 | 帧最大总长度 (16+300+4) |
| `CMD_START` | 0 | 开始传输命令 |
| `CMD_DATA` | 1 | 数据段命令 |
| `CMD_COMPLETE` | 2 | 传输完成命令 |
| `CMD_TERMINATE` | 3 | 终止传输命令 |
| `CMD_UPDATE` | 4 | 触发固件更新命令 |

**解析返回码:**

| 常量 | 值 | 含义 |
|------|----|------|
| `PROTO_OK` | 0 | 解析成功 |
| `PROTO_ERR_PARAM` | 1 | 参数非法 (空指针) |
| `PROTO_ERR_TOO_SHORT` | 2 | 数据长度不足最小帧长 (20B) |
| `PROTO_ERR_HEADER` | 3 | 帧头魔数不匹配 |
| `PROTO_ERR_LENGTH` | 4 | Length 字段 < 12 或 cmd_len > 300 |
| `PROTO_ERR_TAIL` | 5 | 帧尾魔数不匹配 |
| `PROTO_ERR_CHECKSUM` | 6 | 校验和不匹配 |
| `PROTO_ERR_CMD_TOO_SHORT` | 7 | 应答 cmd_len < 2 |

**设计要点:**
- 帧外层的 Length/CommID/DevID 为大端字节序，CmdContent 内部的 fw_ver/fw_size/fw_crc/offset/verify_code 为小端字节序
- 校验和覆盖范围: 偏移 5 到 15+N (不含 Header[0-3] 和 Checksum[4])，即 NetType..CmdContent 共 11+N 字节
- 解析原则: 搜索帧头 FE EF ED FC，容忍目标设备发送的前导字节；只校验帧头/帧尾/长度字段/校验和，**不校验通讯ID/设备ID/主机ID**（目标回复的 ID 可能与约定不同）
- CommID 为模块静态计数器，每次 BuildFrame 自增 (uint16_t 自然回绕)
- `Proto_ParseReply` 复用 `content` 参数作为 in-place 临时缓冲 (先存 cmd 再左移 content)，要求 `content` 至少 300 字节
- 纯逻辑模块，PC 端用 Python 验证 (Tests/test_protocol.py)

### 4.8 sd_card -- SD 卡文件操作

**文件:** `app/sd_card.h`, `app/sd_card.c`

**职责:** 对 FatFs API 的应用层封装，为下载状态机提供简洁的 `SD_Init/FileOpen/FileRead/FileSeek/FileClose` 接口，隐藏 FatFs 内部类型 (FATFS/FIL)。

**依赖:** `ff.h` (FatFs API), `bsp_spi_sd.h`, `app_cfg.h`

**被依赖:** task_download

**关键接口:**

| 函数 | 参数 | 返回值 | 说明 |
|------|------|--------|------|

| `SD_IsPresent()` | 无 | uint8_t: 1=就绪, 0=未就绪 | 返回 g_ready 标志 (不重初始化) |
| `SD_FindLatestFirmware()` | 无 | uint8_t: SD_OK / SD_ERR_NO_FILE | 扫描根目录 IL_800_MMM.SSS.BIN 文件（主/子版本分隔符可为 . 或 _，扩展名大小写不敏感），解析主版本/子版本号，选版本最高者 (major 优先，再比较 sub)；填充 `g_fw_filename` / `g_fw_ver` (fw_ver = major*256+sub) |

- 模块内部静态持有 `FATFS g_fs` 和 `FIL g_file`，上层不暴露 FatFs 类型
- `SD_FileOpen` 幂等: 若 `g_opened == 1` 直接返回 SD_OK，避免上层重复 Open 把 fptr 重置为 0
- 模块全局: `g_fw_filename[32]` (选中的固件文件名) / `g_fw_ver` (fw_ver = major*256+sub) 由 `SD_FindLatestFirmware` 填充，上层 (task_download) 通过 extern 读取

- 错误码翻译: FatFs FRESULT -> SD_ERR_* 枚举
- `SD_IsPresent` 与 `SD_FileOpen` 独立: ready 标志仅检查 SD 卡+卷就绪，不检查文件是否打开

### 4.9 task_key -- 按键扫描任务

**文件:** `app/task_key.h`, `app/task_key.c`

**任务属性:** Prio 25, 栈 1024B, 20ms 周期

**职责:** 每 20ms 扫描 Key1 (PB11) / Key2 (PE14)，软件消抖 + 短按/长按检测，向 `g_key_event_q` 投递事件，通过 `Buzzer_Request()` 请求蜂鸣。

**依赖:** `includes.h`, `task_led_wdg.h`, `sys_state.h`

**被依赖:** app.c (创建任务)

**关键接口:**

| 符号 | 类型 | 说明 |
|------|------|------|
| `g_key_event_q` | `extern OS_Q` | 按键事件队列 (AppTaskStart 中 OSQCreate) |
| `AppTask_Key(void *p_arg)` | 任务入口 | 20ms 周期扫描循环 |
| `KEY_EVT_NONE` | #define 0 | 无事件 |
| `KEY_EVT_B1_LONG` | #define 1 | Key1 长按: 切换数据源 |
| `KEY_EVT_B2_SHORT` | #define 2 | Key2 短按: 启动下载 |
| `KEY_EVT_B2_LONG` | #define 3 | Key2 长按: 切换固件类型 |

**消抖逻辑:**
1. 电平变化 (cur != last_level): 启动消抖 (debouncing=1, debounce_cnt=1)
2. 消抖中 (debouncing=1): debounce_cnt++，达到 2 时确认电平，进入后续处理
3. 按下 (cur==0): press_ticks += 10 (APP_KEY_DEBOUNCE_TICKS)，每 20ms 周期累加
4. 长按触发: press_ticks >= 1000 (APP_KEY_LONG_PRESS_TICKS), long_fired=1 防重复
5. 释放 (cur==1): 若 press_ticks>0 且未触发长按 -> 短按事件 (仅 Key2)

**设计要点:**
- 长按判定: >= 比较而非 ==，容忍扫描延迟导致的漏判
- 传输锁定 (SysState_IsTransferLocked): 所有按键动作完全无响应 (不鸣响、不投递事件)
- 锁定检查在动作触发时刻 (消抖确认后，投递事件前)，保证消抖状态机正常累计/复位，但事件队列不被污染
- 队列满时 OSQPost 失败由发送侧忽略 (最坏情况丢失一次按键事件)
- 使用"指针即数值"约定: OSQPost 第二参数直接强转事件码而非分配缓冲区

**蜂鸣器状态机设计要点:**
- 外部调用 `Buzzer_Request()` 写入 `g_buzzer_cmd` 共享变量 (volatile)，任务循环中消费
- 消费后立即清零 `g_buzzer_cmd`，防止重复执行
- 使用 buzzer_on_ms / buzzer_off_ms / buzzer_repeat / buzzer_pattern 跟踪 ON/OFF 时序
- 每 50ms tick: 若处于 ON 阶段则递减 on_ms，归零后关蜂鸣器、递减 repeat、准备 gap
- gap 阶段递减 off_ms，归零后重开蜂鸣器并重置 on/off 参数 (ERROR 模式 4 次循环)
- 无队列、非阻塞：请求覆盖当前命令 (最坏丢失一次鸣响)

**LED+WDG 设计要点:**
- tick_ms 每 50ms 累加，3000ms 回零 (500 与 1500 的公倍数)，防累积漂移
- wdg_ms 每 50ms +50，达到 2000ms 喂一次狗并清零。IWDG 超时 4s，喂狗间隔 2s = 50% 余量
- 50ms 周期在 500Hz tick (2ms/tick) 下是 25 tick 的整数倍，`OSTimeDlyHMSM` 无量化误差
- 固件类型 LED 每周期幂等重设 (常亮或熄灭)，无需状态跟踪
- TX/RX LED 由 USART 中断和下载任务直接控制，本任务不触碰

### 4.11 蜂鸣器控制 (已合并至 task_led_wdg)

蜂鸣器功能已于 V2.0 重构中合并至 `task_led_wdg` 任务 (见 4.10)。原有独立的 `task_buzzer` 任务 (Prio 24) 和 `g_buzzer_cmd_q` 消息队列均被移除。

**变更概要:**
- 蜂鸣器状态机在 `task_led_wdg` 的 50ms 循环中运行，非阻塞
- 外部通过 `Buzzer_Request(BuzzerCmd_t cmd)` 写入共享变量 `g_buzzer_cmd` (volatile)
- 命令码定义从 `#define` 宏改为 `BuzzerCmd_t` 枚举 (值不变: BOOT=1, SHORT=2, LONG=3, ERROR=4, OK=5)
- 消除了 1 个独立任务 (256B 栈) + 1 个消息队列 (48B 控制块 + 8 深度)，节省 RAM 和调度开销

### 4.12 task_download -- 下载状态机

**文件:** `app/task_download.h`, `app/task_download.c`

**任务属性:** Prio 20, 栈 4096B, 事件驱动 (OS_Q + OS_SEM)

**职责:** 核心任务。实现 7 状态下载状态机: IDLE -> SD_CHECK -> SEND_START -> SEND_DATA -> SEND_COMPLETE -> SEND_UPDATE -> (成功) IDLE；通过 SEND_TERMINATE 终止回 IDLE。

**依赖:** `includes.h`, `task_key.h`, `task_led_wdg.h`, `protocol.h`, `crc32.h`, `sd_card.h`, `sys_state.h`, `bsp_usart.h`, `bsp_gpio.h`, `app_cfg.h`, `<string.h>`

**被依赖:** app.c (创建任务)

**关键接口:**

| 符号 | 类型 | 说明 |
|------|------|------|
| `AppTask_Download(void *p_arg)` | 任务入口 | 状态机主循环 |
| `DL_SendAndWait(...)` | static 函数 | 发送帧 -> 等待信号量 -> 解析应答。返回 status 或 0xFF(超时)/0xFE(解析失败) |
| `DL_SendTerminate(fw_ver, fw_size)` | static 函数 | 发送 Terminate 帧 (无视应答) |
| `DL_CheckGlobalTimeout(start_tick)` | static 函数 | 检查 6min 全局超时 |
| `Buzzer_Request(cmd)` (原 DL_Beep) | 外部函数 (task_led_wdg.h) | 向 LED+WDG 任务共享变量写入蜂鸣器命令 |

**静态缓冲区:**

| 名称 | 大小(B) | 用途 |
|------|---------|------|
| `g_tx_buf` | 320 (FRAME_MAX_TOTAL) | 帧组装输出缓冲 |
| `g_reply_content` | 300 (FRAME_MAX_CMD_LEN) | 应答解析 in-place 缓冲 |
| `g_seg_buf` | 256 (APP_SEGMENT_SIZE) | 单段固件数据缓冲 |

**设计要点:**
- 双层重试: retry_cnt (命令级, 上限 6) 管理超时/WAIT/读失败；error_retry (段级, 上限 6) 管理写错误
- 全局 6min 超时: 每次 SEND_* 状态结尾检查 (360000ms = 180000 tick @500Hz)
- SD 源重定位: 使用 f_lseek 替代 close+reopen+丢弃字节，O(1)；sd_fptr 跟踪文件已读位置，与 offset 比较判断是否需重定位
- 期望地址越界保护: 设备返回 exp_offset >= fw_total_size 时立即终止，防止 remaining 下溢
- 版本不匹配 (STATUS_VER_ERR): 直接终止不重试
- MCU Flash 源: 固定 300KB (APP_FLASH_APP_MAX_SIZE)，直接指针读取 `(APP_FLASH_APP_ADDR + offset)`
- 下载统计: 每次回复打印 `Reply latency` (发送到收到应答耗时) 与 `max byte gap` (相邻字节最大间隔)；下载结束 (SEND_UPDATE) 输出全程 `Max reply latency` / `Max byte gap` 统计
- 1ms 让出 CPU: 每个状态机循环末尾 `OSTimeDlyHMSM(0,0,0,1,...)`，确保其他任务可调度
- 详细状态机说明见 [5. 下载状态机详解](#5-下载状态机详解)

## 5. 下载状态机详解

### 状态转换图

```
                      +-------------------+
                      |      IDLE         |
                      | (等待按键事件)    |
                      +--------+----------+
                               |
                  KEY_EVT_B2_SHORT (启动下载)
                               |
                               v
                      +-------------------+
                      |    SD_CHECK       |
                      | (探测数据源/CRC)  |
                      +--------+----------+
                               |
                     成功 ──────┴────── 失败
                       |                  |
                       v                  v
              +-------------------+    IDLE
              |   SEND_START      |    (错误蜂鸣+解锁)
              | (发送Start帧)     |
              +-------------------+
                       |
          ┌─────OK────┼─────WAIT/超时─────┐
          |            |                   |
          v            v                   v
   SEND_DATA      重试(retry<=6)      TERMINATE(retry>6)
          |        延时1s              TERMINATE(其他错误)
          |
          v
  +-------------------+
  |    SEND_DATA      |<──────────────┐
  | (分段发送256B)    |               |
  +-------------------+               |
          |                           |
    ┌─────OK────┬─────写错误─────────┐
    |           |   (170/175/176/177) |
    |           v                    |
    |      error_retry<=6            |
    |      重定位 offset             |
    |      重试 ─────────────────────┘
    |
    |     VER_ERR(171) ──> TERMINATE (立即)
    |     超时 ──> retry<=6 重试 ──> TERMINATE(retry>6)
    |
    |  offset >= total_size
    v
+-------------------+
|   SEND_COMPLETE   |
| (发送Complete帧)  |
+-------------------+
    |           |
   OK          失败(retry<=6) ──> 重试
    |           TERMINATE(retry>6)
    v
+-------------------+
|   SEND_UPDATE     |
| (发送Update帧)    |
+-------------------+
    |
    v
  IDLE (成功蜂鸣 + 解锁)

=====================================
  任意状态 ──> 全局超时(6min) ──> SEND_TERMINATE ──> IDLE
```

### 各状态详解

#### IDLE

| 项目 | 内容 |
|------|------|
| 触发条件 | 状态机初始化；SEND_UPDATE 或 SEND_TERMINATE 执行完毕 |
| 执行逻辑 | `OSQPend(&g_key_event_q, ...)` 阻塞等待事件 |
| 事件处理 | `KEY_EVT_B1_LONG`: 切换数据源 (检查 SD 卡存在性)|
| | `KEY_EVT_B2_LONG`: 切换固件类型 |
| | `KEY_EVT_B2_SHORT`: 短鸣 -> 加传输锁 -> 记录 start_tick -> 进 SD_CHECK |
| 出口条件 | KEY_EVT_B2_SHORT 且未锁 |

#### SD_CHECK

| 项目 | 内容 |
|------|------|
| 触发条件 | IDLE 收到 KEY_EVT_B2_SHORT |
| 执行逻辑 (SD 源) | 扫描根目录 IL_800_MMM.SSS.BIN -> 从文件名解析主/子版本 -> 选最高版本 (major 优先，再 sub) 打开 -> fw_ver = major*256+sub (取自文件名) -> GetSize -> 整包 CRC32 -> 重开准备传输 |
| 执行逻辑 (Flash 源) | 直接指针读 APP_FLASH_APP_ADDR，固件版本取自内容前 2 字节 fw_ver (LE)；若 fw_ver == 0xFFFF 则判定为无固件，终止下载。fw_total_size=300KB |
| 出口条件 | 成功 -> SEND_START；失败 -> 错误蜂鸣 + 解锁 + IDLE |
| 调试输出 | `[DWN] Starting download: src=..., fw=..., ver=0x..., size=..., crc=0x...` |

#### SEND_START

| 项目 | 内容 |
|------|------|
| 触发条件 | SD_CHECK 成功 |
| 执行逻辑 | `Proto_BuildStartCmd` -> `DL_SendAndWait` |
| STATUS_START_OK (150) | -> SEND_DATA (清零 retry_cnt, error_retry) |
| STATUS_WAIT (100) | 设备忙: retry_cnt++；<=6 时 OSTimeDlyHMSM 1s 后重试；>6 -> SEND_TERMINATE |
| 超时 (0xFF) | retry_cnt++；<=6 重试；>6 -> SEND_TERMINATE |
| 其他 (含 0xFE 鉴权失败) | -> SEND_TERMINATE (立即，不重试) |
| 全局超时 | -> SEND_TERMINATE |

#### SEND_DATA

| 项目 | 内容 |
|------|------|
| 触发条件 | SEND_START 收到 STATUS_START_OK |
| 执行逻辑 | 计算 remaining + seg_size -> SD_FileRead / Flash memcpy -> CRC32_Calc -> Proto_BuildDataCmd -> BSP_LED_Toggle(TX) -> DL_SendAndWait |
| STATUS_DATA_OK (151) | offset += seg_size; 若 offset >= total -> SEND_COMPLETE |
| 写错误 (170/175/176/177) | error_retry++；<=6 从设备期望地址(exp_offset)重发，exp_offset>=total -> TERMINATE；>6 -> TERMINATE |
| STATUS_VER_ERR (171) | -> SEND_TERMINATE (立即终止) |
| 超时 (0xFF) | retry_cnt++；offset 不变，下轮重定位重读；>6 -> TERMINATE |
| 其他 | retry_cnt++；>6 -> TERMINATE |
| SD 源重定位 | sd_fptr != offset 时 `SD_FileSeek(offset)`，O(1) |

#### SEND_COMPLETE

| 项目 | 内容 |
|------|------|
| 触发条件 | SEND_DATA 中 offset >= fw_total_size |
| 执行逻辑 | `Proto_BuildCompleteCmd` -> `DL_SendAndWait` (等待回复超时 8s, `APP_CMD_COMPLETE_TIMEOUT_TICKS`) |
| STATUS_COMPLETE_OK (152) | -> SEND_UPDATE |
| 其他 | retry_cnt++；<=6 重试；>6 -> TERMINATE |

#### SEND_UPDATE

| 项目 | 内容 |
|------|------|
| 触发条件 | SEND_COMPLETE 收到 STATUS_COMPLETE_OK |
| 执行逻辑 | `Proto_BuildUpdateCmd` -> `DL_SendAndWait` |
| STATUS_UPDATE_OK (154) | 成功蜂鸣 OK |
| 其他 | 错误蜂鸣 |
| 出口条件 | 无论成败: 解锁 + 关闭 SD 文件 + -> IDLE |

#### SEND_TERMINATE

| 项目 | 内容 |
|------|------|
| 触发条件 | 任何状态的错误超过重试上限 |
| 执行逻辑 | `DL_SendTerminate` (发 Terminate 帧，无视应答) + 错误蜂鸣 |
| 出口条件 | 解锁 + 关闭 SD 文件 + -> IDLE |

### 超时与重试机制表

| 机制 | 适用范围 | 阈值 | 单位 | 超出行为 |
|------|----------|------|------|----------|
| 命令超时 | 每帧收发 | Start/Data/Update/Terminate=1000ms；Complete=8000ms | APP_CMD_TIMEOUT_MS / APP_CMD_COMPLETE_TIMEOUT_MS | DL_SendAndWait 返回 0xFF |
| 命令级重试 | 超时/WAIT/其他/读失败 | 6 次 | APP_CMD_MAX_RETRY | SEND_TERMINATE |
| 段级重试 | 写错误 (170/175/176/177) | 6 次 | APP_ERROR_MAX_RETRY | SEND_TERMINATE |
| 全局超时 | 整个下载流程 | 6 分钟 | APP_GLOBAL_TIMEOUT_MIN | SEND_TERMINATE |

**注意:** STATUS_WAIT(100) 使用了 1s 延迟重试 (`OSTimeDlyHMSM(0,0,1,0,...)`)，而超时重试无延迟。STATUS_VER_ERR(171) 和鉴权失败(STATUS_AUTH_FAIL=101) 不重试，立即终止。

## 8. 配置指南

### 8.1 app_cfg.h 配置项说明

所有应用级配置集中在 `app/app_cfg.h`，见 [4.14 app_cfg.h](#414-appcfgh--应用配置) 的完整表格。

### 8.2 os_cfg.h 关键配置

- `OS_CFG_PRIO_MAX = 32`: 支持 0-31 共 32 个优先级。当前使用 10-31 范围，若需更多用户任务可增大此值
- `OS_CFG_APP_HOOKS_EN = 1`: 使能应用钩子 (当前所有钩子为空)

### 8.3 ffconf.h FatFs 配置

见 [4.16.3 ffconf.h](#4163-ffconfh--fatfs-配置)。关键: 只读 (FF_FS_READONLY=1)，重入保护 (FF_FS_REENTRANT=1, 使用 UCOS-III 互斥量)，长文件名 (FF_USE_LFN=1, IL_800_MMM.SSS.BIN 命名需要 LFN 支持)。

### 8.4 修改段大小/超时/重试次数的方法

修改 `app/app_cfg.h` 中对应宏:

```c
#define APP_SEGMENT_SIZE        256u   /* 段大小 (B)      */
#define APP_CMD_TIMEOUT_MS      1000u  /* 命令超时 (ms)    */
#define APP_CMD_COMPLETE_TIMEOUT_MS  8000u  /* Complete 命令超时 (ms) */
#define APP_CMD_MAX_RETRY       6u     /* 命令级重试次数   */
#define APP_ERROR_MAX_RETRY     6u     /* 段级重试次数     */
#define APP_GLOBAL_TIMEOUT_MIN  6u     /* 全局超时 (分钟)  */
```

**注意事项:**
- 修改 `APP_SEGMENT_SIZE` 后需同步修改 `APP_FRAME_MAX_DATA` (应 >= segment_size + 16)
- 修改 `APP_CMD_TIMEOUT_MS` 后需同步修改 `APP_CMD_TIMEOUT_TICKS` (= ms/2, 因 500Hz tick)
- 协议帧最大长度为 FRAME_MAX_TOTAL=320 字节，数据段过大可能导致帧缓冲区溢出

### 8.5 增加新任务的方法

1. 在 `app/app_cfg.h` 中定义任务优先级、栈大小 (例如 `APP_TASK_NEW_PRIO 27u`)
2. 创建任务源文件 `app/task_new.c` 和头文件 `app/task_new.h`
3. 任务入口函数签名为 `void AppTask_New(void *p_arg)`
4. 在 `app/includes.h` 中添加 `#include <task_new.h>`
5. 在 `app/app.c` 的 `AppTaskStart` 中:
   - 定义 TCB: `OS_TCB AppTaskNewTCB;`
   - 定义栈: `__align(8) static CPU_STK AppTaskNewStk[APP_TASK_NEW_STK_SIZE];`
   - 调用 `OSTaskCreate(...)` 创建任务
6. 确保新任务优先级不与其他任务冲突 (内核任务 10/22/23/31，用户任务目前 20/25/26/28)
7. 如使用 IPC，在 `AppTaskStart` 中创建对应的内核对象 (OS_Q, OS_SEM 等)

## 10. 调试指南

### USART2 调试输出说明

所有调试信息通过 USART2 (PD5/PD6, 115200-8N1) 输出。各模块使用独立前缀:

| 前缀 | 模块 | 典型输出示例 |
|------|------|-------------|
| `[DWN]` | task_download (下载状态机) | `[DWN] Starting download: src=SD_CARD...` |
| `[DWN]` | task_download | `[DWN] Seg 0x00001000: 256B (50.0%)` |
| `[DWN]` | task_download | `[DWN] Start: WAIT (100) retry 2/6` |
| `[DWN]` | task_download | `[DWN] Reply latency: 12 ms, max byte gap: 2 ms` (每帧回复统计) |
| `[DWN]` | task_download | `[DWN] Max reply latency: 15 ms` / `[DWN] Max byte gap: 8 ms` (下载结束统计) |
| `[FAT]` | FatFs ff.c (通过 FF_DEBUG) | FAT 内部跟踪信息 (ff.c 的 f_printf) |
| 无前缀 | app.c | `FW Downloader V2.0 Ready.` |
| 无前缀 | app.c | `Warning: SD card not detected.` |

### FF_DEBUG 开关

`ffconf.h` 中 `FF_DEBUG = 1` 使能 FatFs 调试输出。关闭 (置 0) 后 ff.c 内部 f_printf 不会编译，零开销。

### 常用调试场景

| 场景 | 观察点 | 预期现象 |
|------|--------|----------|
| SD 卡未插入 | USART2 输出 | 启动时打印 "Warning: SD card not detected." |
| 按 Key2 短按 | 蜂鸣器 + USART2 | 短鸣一声 + `[DWN] Starting download...` |
| 下载进行中 | TX LED + USART2 | PA12 每段翻转 + `[DWN] Seg 0x...:...` |
| 下载成功 | 蜂鸣器 + USART2 | 长鸣一声 + `[DWN] Update: OK (154) - SUCCESS!` |
| 下载超时 | 蜂鸣器 + USART2 | 四声短鸣 + `[DWN] GLOBAL TIMEOUT...` |
| 传输锁定 | 按键 | 下载进行中按任何键无响应 |
| IWDG 喂狗 | LED_SYS 闪烁 | PB12 按周期闪烁 (SD=500ms, Flash=1500ms) |

### 常见问题排查

| 问题 | 可能原因 | 排查方法 |
|------|----------|----------|
| SD 卡无法初始化 | SPI 接线错误 / 卡电压不匹配 | 检查 SD_SPI_Init 返回值; CMD0 应返回 0x01 |
| 下载无应答 | USART1 接线错误 / 目标设备未上电 | 用逻辑分析仪抓 PA9/PA10 波形 |
| 帧校验失败 | 大小端错误 / CRC32 参数不匹配 | 用 Python 测试套件验证帧格式 |
| 每次重试均超时 | USART1 中断优先级被更高中断抢占 | 检查 NVIC 配置; USART1 抢占优先级=1 |
| 按键不响应 | 传输锁未释放 | 检查 `SysState_IsTransferLocked` 返回 |
