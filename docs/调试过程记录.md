# 固件下载器调试过程记录

> 记录从 v0.01 到 v0.1 开发调试中遇到的所有问题、根因与解决方法。
> 供后续维护参考，避免重蹈覆辙。

---

## 一、编译问题

### 1. 注释中 `*/` 误闭合块注释
- **现象**：`task_led_wdg.c` 编译报错，一堆 `LED_FW_` 未定义
- **根因**：注释行 `*   - LED_SYS_*/LED_FW_* 宏` 中的 `*/` 提前结束了块注释
- **修复**：改为 `LED_SYS_xxx, LED_FW_xxx`，避免 `*/` 序列
- **教训**：注释中不要出现 `标识符*/标识符` 模式

### 2. FIL 结构体缺字段
- **现象**：`ff.c` 编译报 `fsize` 字段不存在
- **根因**：自定义 FIL 结构体缺 `fsize` 成员
- **修复**：补上 `FSIZE_t fsize`

### 3. 函数重复定义
- **现象**：`USART1_IRQHandler multiply defined`
- **根因**：输出目录残留旧版 `bsp_usart.o`（旧版直接定义了 ISR）
- **修复**：删除旧 .o 文件 + Rebuild All
- **教训**：修改 ISR 名称后必须全量重编译

## 二、SD 卡驱动调试（最耗时）

### 1. SPI 引脚配置错误
- **现象**：CMD0 一直失败，R1=0xFF
- **根因1**：PB14 (MISO) 配置成 `GPIO_Mode_AF_PP`（复用推挽输出），总线冲突
- **修复**：改为 `GPIO_Mode_IN_FLOATING`（或 IPU）
- **根因2**：SPI 模式用错（Mode 3 vs Mode 0）
- **修复**：最终确认 Mode 3 (CPOL=High, CPHA=2Edge) 与本硬件匹配

### 2. CS 复位问题
- **现象**：重试 CMD0/ACMD41 一直失败
- **根因**：连续重试时 CS 未拉高复位卡内 SPI 状态机
- **修复**：每次重试前 `CS_High → 8时钟 → CS_Low`

### 3. 响应轮询方式
- **现象**：读一个字节判断响应，拿到 0xFF 就失败
- **根因**：SD 卡发完命令先回 0xFF（忙），R1 稍后才到
- **修复**：`SD_GetResponse` 轮询最多 0xFFF 字节直到匹配
- **教训**：SPI 读响应必须轮询，不能只读一次

### 4. 命令第 6 字节处理
- **现象**：低速(140kHz)时第6字节是 0xFF，高速(18MHz)时第6字节就是 R1
- **根因**：高速下响应提前到达
- **修复**：统一用 6 字节后轮询方式（兼容两种速度）

### 5. UCOS-III 抢断破坏 SPI 时序
- **现象**：关中断时 CMD0 成功，开中断后 CMD8 失败
- **根因**：任务调度/中断在 SPI 字节传输间隙抢断，破坏时序
- **修复**：每个 SPI 命令（CS_Low→收发→CS_High）用 `CPU_CRITICAL_ENTER/EXIT` 保护
- **教训**：**RTOS 下 SPI 字节级操作必须临界区保护**

### 6. 低速/高速切换
- **现象**：初始化 18MHz 失败
- **根因**：SD 规范要求初始化 ≤400kHz
- **修复**：`BSP_SPI2_Init` 用 140kHz，`SD_SPI_Init` 成功后 `SD_SPI_SetHighSpeed()` 提到 18MHz
- **注意**：改 BR 前必须先 `SPI_Cmd(DISABLE)`（STM32 规范）

### 7. SDHC/SDSC 寻址差异（关键）
- **现象**：`f_mount` 失败 FR_NO_FILESYSTEM，扇区63读到垃圾
- **根因**：卡是 SDSC（≤2GB），设 HCS=1 仍保持字节寻址；CMD17 传 LBA 被当作字节偏移
- **修复**：ACMD41 后发 CMD58 读 OCR 的 CCS 位判断卡类型；SDSC 下 CMD17 地址 ×512
- **教训**：**HCS 只是能力声明，卡类型是物理固定的**

### 8. MBR 分区表
- **现象**：`f_mount` 失败，扇区0是 MBR 而非 FAT VBR
- **根因**：卡有 MBR 分区表，FAT 引导扇区在分区起始（LBA 63）
- **修复**：`FF_MULTI_PARTITION=1` + `VolToPart[0]={0,1}`

### 9. SPI 重复初始化
- **现象**：二次初始化后 CMD0 失败
- **根因**：`disk_initialize`/`SD_Init` 重复调 `BSP_SPI2_Init`，SPE=1 时改 BR 违反规范
- **修复**：移除冗余初始化，SD 卡只初始化一次

### 10. FatFs 桩文件 → 真实实现 → 官方
- **过程**：先写桩（无法读卡）→ 自写只读 FAT16/32（Python 测试通过）→ 用户下载官方 R0.15 替换
- **关键**：官方 ff.c 需要 `ffunicode.c`（LFN 用）、`FF_FS_REENTRANT=1` 需要 `ff_ucos3.c`

## 三、下载协议调试

### 1. 帧长度字段错误（关键）
- **现象**：目标设备回复异常/不回复
- **根因**：长度字段 = 11+N，实际应为 **报文总长-8 = 12+N**（少算了校验字节）
- **修复**：Build 和 Parse 同步改 12+N；Python 测试同步
- **教训**：发送端/解析端/测试三处必须一致

### 2. 前导字节
- **现象**：目标回复前带一个 `FE`，解析失败 ret=3
- **根因**：设备回复有前导字节，解析器严格要求 raw[0..3]==帧头
- **修复**：解析器**搜索帧头** FE EF ED FC，容忍前导字节
- **验证**：去掉前导 FE 后，命令 `00 96` = 状态150（启动成功）

### 3. ID 字段不校验
- **现象**：设备回复的设备 ID 是 0x00030D3F，非约定 999999
- **修复**：解析只校验帧头/帧尾/长度/校验和，不校验通讯ID/设备ID/主机ID

### 4. 波特率
- **现象**：目标不回复
- **修复**：USART1 从 115200 改为 **38400**

### 5. USART1 上电自测污染（关键）
- **现象**：等待回复不到 1 秒就返回
- **根因**：上电自测字符串 `USART1_TX_OK` 回环到 RX，触发信号量残留计数=1
- **修复**：移除自测 + `BSP_USART1_RecvStart` 用 `OSSemSet` 清零信号量

### 6. IDLE 中断死循环（关键）
- **现象**：系统卡死，一直进 USART1_IRQHandler
- **根因**：启用了 IDLE 中断但 ISR 不处理，空闲时 IDLE 标志常置位
- **修复**：禁用 IDLE 中断，改用 TIM3 超时判定帧结束

### 7. 接收帧判定机制
- **现象**：设备回复不连续，IDLE 截帧不准
- **修复**：TIM3 10ms 计时 + 字节数阈值：
  - 字节间超时 **80ms** → 上报
  - 累积 >128 字节 → 立即上报
- **演进**：300ms → 200ms → 150ms → 80ms（根据 max byte gap 调优）

### 8. 假帧 F8 78 80
- **现象**：RX 收到重复的 `F8 78 80`，设备没发这些
- **排查**：改 PA10 IPU（外部已有上拉，非根本原因）→ 检查接收缓冲（正确）→ 加 SR 标志诊断
- **结论**：待进一步确认（可能是波特率或线路问题，用 SR 标志定位）

### 9. 各命令回复超时
- **修复**：Start/Data/Update/Terminate = 1s，**Complete = 8s**（设备写 Flash 慢）

### 10. 性能统计
- **新增**：每条命令输出 `Reply latency` + `max byte gap`
- **新增**：下载完成输出全程 Max reply latency / Max byte gap

## 四、系统级问题

### 1. 栈溢出死机
- **现象**：按下载键后死机
- **根因**：DL_SendAndWait 里大栈数组（TX 984B + RX 1560B），超出 4KB 任务栈
- **修复**：hex dump 改为 128 字节（栈 408B）+ Download 任务栈 4KB→8KB

### 2. 残留对象文件
- **现象**：链接错误，旧 IL-800 产品符号未定义
- **根因**：输出目录 D:\output\MDK\IL-800\DEBUG\ 残留旧产品 .o 文件
- **修复**：清空输出目录 + Rebuild All

## 五、调试工具与方法总结

| 工具/方法 | 用途 |
|-----------|------|
| TX/RX 帧 hex dump | 验证收发字节结构 |
| SR 状态寄存器诊断 | 判断 FE(波特率)/ORE(溢出)/NE(噪声) |
| Reply latency | 命令回复总耗时 |
| max byte gap | 设备回复字节间隔，优化接收超时 |
| 关中断对比测试 | 定位 RTOS 抢断问题 |
| Python 单元测试 | 纯逻辑模块（协议/CRC/FAT）验证 |

## 六、关键经验

1. **RTOS + SPI 字节级操作必须临界区保护**
2. **SD 卡寻址（SDHC/SDSC）必须 CMD58 检测**
3. **帧长度字段定义要发送/解析/测试三处一致**
4. **信号量残留计数导致 OSSemPend 立即返回**
5. **禁用的中断要确认已关闭（IDLE 死循环教训）**
6. **大栈数组是嵌入式死机常见原因**
7. **残留 .o 文件导致链接到旧代码**
